# 数独ソルバー Web アプリ 実装プラン

## Context
`rdd.txt` の要件定義に基づき、ゼロから静的 Web アプリを構築する（現状リポジトリは `rdd.txt` のみで git 未初期化）。要件:
- 数独を解くプログラム、ロジックは JavaScript・Web 単体で完結
- 対象端末: iPhone / Android、対象ブラウザ: Chrome / Safari
- カメラまたは写真からのデータ入力（可能であれば → ユーザーとの相談の結果、今回のスコープに含める）
- GitHub Pages で html として公開

追加確認の結果、以下も含める:
- ビルド不要の素の HTML/CSS/JS 構成
- 数独パズルの自動生成機能（新しい問題を作る）

## 全体構成（ビルド不要・CDN 併用）

```
/index.html
/css/style.css
/js/
  main.js       … 初期化・イベント配線・画面状態(state)管理
  board.js      … 9x9盤面のレンダリング／セル選択／数字パッド入力／矛盾ハイライト
  solver.js     … バックトラッキング＋ビット演算による数独ソルバー、解の一意性判定
  generator.js  … 完成盤生成＋穴あけ（一意解を保ちながら）による問題生成、難易度別
  ocr.js        … 写真/カメラ入力 → 盤面認識パイプライン（OpenCV.js + Tesseract.js）
/README.md
```
外部ライブラリ（OpenCV.js, Tesseract.js）は CDN から読み込み、npm/ビルドステップは使わない。`docs/` は使わず、リポジトリルートを GitHub Pages の公開元にする。

## 機能ごとの実装方針

### 1. 盤面 UI（board.js）
- 9x9 グリッドを div/button セルで描画（3x3 太枠）。
- モバイルでネイティブキーボードが暴れないよう、セルタップ→下部の数字パッド(1-9, 消去)で入力する方式（物理キーボードの数字キー入力にも対応）。
- 「与えられた数字（given/OCR確定値）」と「解答で埋めた数字」を色分け。
- 入力中はリアルタイムで行・列・3x3ブロックの重複を赤くハイライト。

### 2. ソルバー（solver.js）
- 行・列・ブロックごとの候補をビットマスクで管理するバックトラッキング法（9x9なら十分高速）。
- `solve(grid)`（1解を返す）と `countSolutions(grid, limit)`（一意性判定用、上限で打ち切り）を提供し、generator.js からも再利用。
- 解なし／矛盾のある入力はボタン押下時にエラー表示。

### 3. パズル自動生成（generator.js）
- ランダム順のバックトラッキングで完成盤を1つ生成。
- セルをランダム順に1つずつ空にし、その都度 `countSolutions` で解が唯一であることを確認しながら削る（唯一でなくなったら戻す）。
- 難易度（易/中/難）ごとに目標のヒント数（例: 40 / 32 / 26）を設定し、「New Puzzle」ボタンと難易度選択 UI を用意。

### 4. カメラ/写真入力（ocr.js）
- `<input type="file" accept="image/*" capture="environment">` を使用（getUserMedia のライブプレビューは iOS Safari 対応の複雑さを避けるため不採用）。OS標準の「写真を撮る/ライブラリから選ぶ」ダイアログが両要件（カメラ・写真）を満たす。
- パイプライン: 画像→canvas → OpenCV.js で最大の四角形輪郭（盤面外枠）を検出 → 射影変換で正面化 → 81セルに等分割 → 各セルを二値化し空セル判定 → 数字ありセルのみ Tesseract.js（`tessedit_char_whitelist=123456789`, PSM=単一文字）で認識。
- OCR誤読は避けられないため、認識結果を盤面にプレビュー表示し、ユーザーが確認・修正してから「解く」を押すフローを必須にする。
- 初期ロードを軽くするため、OpenCV.js / Tesseract.js は「写真から入力」操作時に遅延ロードする。

### 5. レスポンシブ／クロスブラウザ
- viewport meta、モバイルファーストCSS、タッチ操作前提（hover依存UIなし）。
- Chrome (Android/デスクトップ) と Safari (iOS/macOS) で手動確認。

### 6. GitHub Pages 公開
- リポジトリを `git init` し、上記ファイル一式をコミット。
- リポジトリ設定で GitHub Pages を「main ブランチ・ルート」から公開するよう案内（実際の push/リモート作成はユーザー確認の上で実施）。
- 簡単な README（使い方・対応ブラウザ・機能一覧）を追加。

## 実装順序（フェーズ）
1. 雛形: git init、フォルダ構成、`index.html`/`style.css` の骨組み、レスポンシブ基本レイアウト
2. 盤面UI: グリッド描画、数字パッド入力、矛盾ハイライト
3. ソルバー: `solve`/`countSolutions` 実装、「解く」「クリア」ボタン結線
4. 自動生成: 完成盤生成＋穴あけ、難易度選択、「New Puzzle」ボタン
5. OCR入力: ファイル入力→OpenCV.jsで枠検出/正面化→セル分割→Tesseract.jsで数字認識→確認・修正UI→盤面反映
6. 仕上げ・公開: モバイル実機/DevTools確認、README作成、GitHub Pages 設定案内

## 検証方法
- ローカルで `python3 -m http.server` 等の簡易サーバーを立て、Chrome DevTools のモバイルエミュレーションで表示・操作確認。
- ソルバー: 既知の数独問題（解が判明しているもの）を盤面に入力し、期待する解と一致するかブラウザ console で確認。
- 生成機能: 生成した問題をそのままソルバーで解けること、および `countSolutions` が1であることを確認。
- OCR: 印刷された数独やスクリーンショットの写真で認識精度を確認し、誤読セルを手動修正できることを確認（自動テストは困難なため手動検証）。
- 可能であれば実機の iPhone Safari / Android Chrome で最終確認。
